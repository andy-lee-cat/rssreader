# Miniflux 项目架构文档

## 概述

Miniflux 是一个用 Go 语言编写的极简主义 RSS 阅读器。项目采用单体架构，包含 Web UI、REST API、多种第三方 API 兼容层，以及后台任务调度系统。

---

## 四、internal/ - 核心业务逻辑

这是项目的核心，包含所有业务逻辑。

### 4.1 入口与配置层

| 目录 | 说明 |
|------|------|
| `cli/` | 命令行解析、程序入口（daemon启动、数据库迁移等） |
| `config/` | 配置管理（环境变量、配置文件解析） |

**启动流程**:
```
main.go → cli.Parse() → 解析配置 → 初始化数据库 → startDaemon()
                                                    ↓
                                             启动 HTTP 服务器
                                             启动 Worker Pool
                                             启动 Scheduler
```

### 4.2 数据层

| 目录 | 说明 |
|------|------|
| `model/` | 数据模型定义（User, Feed, Entry, Category 等） |
| `storage/` | 数据库操作（CRUD、查询构建器） |
| `database/` | 数据库连接池、迁移管理 |

**核心模型关系**:
```
User 1:N Category 1:N Feed 1:N Entry
                          ↓
                       Enclosure (附件)
```

**storage 关键文件**:
- `entry_query_builder.go` - Entry 查询构建器（支持复杂过滤）
- `feed_query_builder.go` - Feed 查询构建器
- `entry.go` - Entry CRUD 操作
- `feed.go` - Feed CRUD 操作

### 4.3 HTTP 服务层

| 目录 | 说明 |
|------|------|
| `http/server/` | HTTP 服务器启动、TLS 配置 |
| `http/request/` | 请求解析工具 |
| `http/response/` | 响应构建工具 |
| `http/route/` | 路由辅助函数 |
| `http/cookie/` | Cookie 管理 |

**路由注册**: 在 `http/server/httpd.go` 中统一注册各模块路由：
```go
router := mux.NewRouter()
ui.Serve(router, store, pool)        // Web UI
api.Serve(router, store, pool)       // REST API
fever.Serve(router, store)           // Fever API
googlereader.Serve(router, store)    // Google Reader API
```

### 6.2 集成方式选择

#### 方式一：通过 REST API 集成（推荐）

**优点**:
- 完全解耦，Agent 独立运行
- 复用现有 API 认证机制
- 易于测试和调试

**实现**:
```python
# ai-agent/tools/rss_tools.py
import miniflux  # 使用官方 Python 客户端

def get_entry_content(entry_id: int) -> str:
    client = miniflux.Client(base_url, api_key)
    entry = client.get_entry(entry_id)
    return entry["content"]
```

**需要扩展的 API**:
- `GET /v1/entries/{id}/content` - 获取纯文本内容
- `PUT /v1/entries/{id}/ai-summary` - 保存 AI 摘要

#### 方式二：通过 gRPC/消息队列集成

**优点**:
- 更高性能
- 支持流式通信

**实现**:
- 在 `internal/` 下新增 gRPC 服务
- Agent 通过 gRPC 调用

#### 方式三：数据库直接访问

**优点**:
- 最简单的实现
- 无需额外 API

**缺点**:
- 紧耦合
- 需要共享数据库连接配置

**实现**:
```python
# ai-agent/tools/db_tools.py
import psycopg2

def get_entry_content(entry_id: int) -> str:
    conn = psycopg2.connect(DATABASE_URL)
    cursor = conn.cursor()
    cursor.execute("SELECT content FROM entries WHERE id = %s", (entry_id,))
    return cursor.fetchone()[0]
```

### 6.3 推荐实施步骤

1. **第一阶段：建立通信桥梁**
   - 在 Go 端扩展 REST API，添加 AI 相关端点
   - 或添加 gRPC 服务端点

2. **第二阶段：创建 Agent 框架**
   - 在 `ai-agent/` 目录创建 LangGraph 项目
   - 实现基础工具（获取 RSS 内容、保存摘要）

3. **第三阶段：实现具体功能**
   - RSS 文章摘要
   - 智能分类建议
   - 内容推荐

4. **第四阶段：优化与监控**
   - 添加缓存层
   - 实现请求限流
   - 添加监控指标

### 6.4 建议新增的 Tools 接口

```go
// internal/ai/tools.go

// AITool 定义 Agent 可调用的工具接口
type AITool interface {
    Name() string
    Description() string
    Execute(ctx context.Context, params map[string]any) (any, error)
}

// GetEntryContentTool 获取文章内容
type GetEntryContentTool struct {
    store *storage.Storage
}

func (t *GetEntryContentTool) Execute(ctx context.Context, params map[string]any) (any, error) {
    entryID := params["entry_id"].(int64)
    entry, err := t.store.EntryByID(entryID)
    if err != nil {
        return nil, err
    }
    return map[string]string{
        "title":   entry.Title,
        "content": entry.Content,
        "url":     entry.URL,
    }, nil
}
```
